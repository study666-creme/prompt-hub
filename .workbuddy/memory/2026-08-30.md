## 卡片库入场动效 + 首屏性能

### 首屏真凶：39 次串行同步 XHR

首屏实际用 **39 次串行同步 XHR** 取内容（6 个 `partials/index-body/part-*.html` +
13 `legacy/script` + 7 `legacy/supabase-sync` + 13 `legacy/features-draft`，约 1.36MB）。
同步 XHR 冻结主线程，串行又让每个分片各付一次 RTT —— 这是「很卡尤其是首屏」的主因。

修法：`index.html` 在 `<head>` 解析期用 `fetch` 一次性并行发出全部请求，文本存进
`window.__PH_PART_STORE__.text`（键 = 分片相对路径，**不含** `?v=`，所以版本号不匹配
也不会取错文件，最坏只是多取一次）。同步加载器先查表，未命中才退回同步 XHR —— 纯增益，
无新失败模式。关键路径 `priority: 'high'`，`features-draft`/`supabase-sync` 用 `'low'`。

拆分加载器是生成物，模板在 `scripts/create-legacy-runtime-split.mjs`，已同步改好；
现有 7 个 root loader 已手工迁移一致。

CSS 也修掉 `@import` 瀑布：`styles.css`/`styles-features.css` 只是清单，20 个真实分片
要多等一次阻塞往返。`index.html` 用 `__PROMPT_HUB_CSS_PRELOAD_START__/END__ <entry>`
标记维护 preload 块（标记带 entry 名，否则多份清单会互相覆盖），版本由
`scripts/create-css-runtime-split.mjs` 重新拆分时同步重写。

实测（本机 HTTP/1.1，56 请求争 6 连接，悲观下限）：同步 XHR 39→6，DCL 960ms→554ms。

### 卡片入场：死代码 + 两个硬约束

`styles/base/part-09.css` 的 `.card-enter-soft` 从未被 JS 使用，且选择器
`#cardsContainer > .card...` 只匹配**直接子**卡片，而列容器瀑布流把卡片放进
`.warehouse-focus-col` —— 永远命中不了。所以卡片一直是硬生生出现。

两个必须遵守的约束（踩过的坑）：
1. **必须用 transition，不能用 animation**。瀑布流分发会 `appendChild` 移动节点，
   移动会重启 CSS animation —— 这正是当年「整片卡片疯狂闪动」导致动效被摘掉的根因。
2. **位移必须放 `.card-media`/`.card-body`，不能放 `.card`**。`.card` 的 `transform`
   已被 hover（`translateY(-6px) scale(1.01x)`）占用，叠在一起会互相打断。

实现：`markWarehouseCardsPending`（布局前隐藏）→ 布局 → `revealWarehouseCards`
（`legacy/script/part-03.js`）。28ms/张错峰、最多 10 档；结束后摘掉 `card-enter-in`
（它覆盖 `.card` 原 transition，留着 hover 会变迟钝）；1500ms 保险丝防卡片停在
`opacity: 0`；`prefers-reduced-motion` 下 JS 直接跳过。
