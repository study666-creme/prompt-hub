## 下午：真瀑布流回归（commit 2befd61）

用户反馈"上一个对话把瀑布流调成了方格，这可不行"，以及卡片库多列疯狂闪动。排查结果：

1. **列容器瀑布流根本没生效**（根因）：`flattenWarehouseFocusColumns`
   （`legacy/script/part-03.js`）只在 `.warehouse-focus-col` 里取卡片，首次分发时
   卡片仍是容器直属子元素 → 返回空数组 → `distributeWarehouseFocusColumns` 早退 →
   列容器永远建不起来 → 卡片退化成 `display:block` 单列堆叠。
   验证脚本报 `firstRowTopSpread: 4058`。
   修复：同时收集容器直属卡片，并用 `data-wh-order` 稳定序号还原顺序
   （列容器会把卡片按"列0整列、列1整列"的文档顺序打乱）。

2. **媒体框占位才是"方格"和"闪动"的来源**（`styles/base/part-09.css`）：
   `.card-media--await` 带 `max-height: 200px`，把所有卡片压成等高方格；
   而实际加载中占位高度只有 ~1px，加载完直接跳到 397/529px。
   修复：占位改为 `:not(.media-revealed)` 用 `3/4` + `min-height: 72px`，
   **绝不能再加 max-height**；加载完成后放开为 `aspect-ratio: auto`。
   实测占位 396px → 397/529px，跳变极小，`movedBetweenColumns` 从 5 张降到 0 张。

3. 验证脚本断言适配列容器：DOM 顺序是列优先，不能拿前 N 张卡片的 top 比，
   改为比较**各列首卡**的 top 对齐（`firstRowTopSpread`）。

4. 版本号 `20260829l` → `20260829m`（index.html / sw.js / admin*.html / asset-studio.html）。
   用户截图里显示 `版本 20260829k`，说明浏览器缓存了旧包，升版本才能失效。

5. 同步文档并明确标注 CSS multi-column 与固定 4/3 媒体框**已弃用**：
   CARD-LOADING / FILE-MAP / AI-HANDOFF / BACKEND / RECONCILE。
   注意：这 4 个文档此前仍把"固定 4/3 媒体框"写成现行方案，与代码已经不符。
